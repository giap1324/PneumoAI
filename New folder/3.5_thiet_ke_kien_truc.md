# 3.5. Thiết kế kiến trúc hệ thống

Kiến trúc hệ thống của giải pháp chẩn đoán viêm phổi **PneumoScan AI** được thiết kế theo mô hình kiến trúc phân tầng (Layered Architecture/Multitier Architecture). Mô hình này chia hệ thống thành các lớp độc lập có nhiệm vụ chuyên biệt, giúp tăng cường khả năng bảo trì, mở rộng hệ thống và nâng cao tính an toàn thông tin. Hệ thống bao gồm 4 tầng cốt lõi: Tầng Trình diễn (Presentation Layer), Tầng Dịch vụ ứng dụng (Application Service Layer), Tầng Suy luận trí tuệ nhân tạo (AI Inference Layer) và Tầng Dữ liệu (Data Layer).

---

## 3.5.1. Tổng quan về mô hình kiến trúc hệ thống

Sơ đồ tổng quan kiến trúc hệ thống được phân rã thành mô hình giao tiếp 4 tầng đồng bộ như sau:

```
┌────────────────────────────────────────────────────────┐
│               PRESENTATION LAYER (CLIENTS)             │
│  ┌────────────────────────┐    ┌────────────────────┐  │
│  │     Website Client     │    │   Mobile Client    │  │
│  │ (HTML5/Jinja2/Streamlit)│    │   (Flutter App)    │  │
│  └───────────┬────────────┘    └─────────┬──────────┘  │
└──────────────┼───────────────────────────┼─────────────┘
               │ HTTP/HTTPS RESTful Requests│
               ▼                           ▼
┌────────────────────────────────────────────────────────┐
│          APPLICATION SERVICE LAYER (FASTAPI SERVER)    │
│  ┌──────────────────────────────────────────────────┐  │
│  │                  API Gateway                     │  │
│  │  - Router & Controller    - DB Failover Manager  │  │
│  │  - Static Files Handler   - Upload Manager       │  │
│  └───────────────────────┬──────────────────────────┘  │
└──────────────────────────┼─────────────────────────────┘
                           ├────────────────────────┐
                           ▼                        ▼
┌──────────────────────────────────────┐ ┌──────────────────────┐
│          AI INFERENCE LAYER          │ │      DATA LAYER      │
│  ┌──────────────────────────────┐     │ │ ┌──────────────────┐ │
│  │         HybridViT            │     │ │ │   Primary DB     │ │
│  │ (DenseNet121 + Transformer)  │     │ │ │    (MySQL)       │ │
│  └──────────────┬───────────────┘     │ │ └────────┬─────────┘ │
│                 ▼                     │ │          │ Failover │
│  ┌──────────────────────────────┐     │ │ ┌────────▼─────────┐ │
│  │       GradCAM Module         │     │ │ │   Fallback DB    │ │
│  │   (denseblock3 target)       │     │ │ │    (SQLite)      │ │
│  └──────────────────────────────┘     │ │ └──────────────────┘ │
│                                       │ │ ┌──────────────────┐ │
│                                       │ │ │   File Storage   │ │

└──────────────────────────────────────┘ └──────────────────────┘
```

Luồng xử lý dữ liệu chung của hệ thống diễn ra như sau:
1.  Người dùng (Bác sĩ hoặc Kỹ thuật viên) tương tác với **Tầng Trình diễn** (Web hoặc Mobile App) để tải lên ảnh X-Quang ngực và nhập thông tin bệnh nhân.
2.  Yêu cầu được đóng gói và gửi dưới dạng HTTP/HTTPS RESTful API đến **Tầng Dịch vụ** (FastAPI Gateway).
3.  Tầng Dịch vụ thực hiện lưu trữ ảnh gốc, sau đó chuyển giao dữ liệu ảnh nhị phân sang **Tầng Suy luận AI** để thực hiện phân tích bằng mô hình mạng nơ-ron lai ghép HybridViT và tính toán bản đồ nhiệt trực quan hóa bằng GradCAM.
4.  Kết quả chẩn đoán và hình ảnh được liên kết lưu trữ vào **Tầng Dữ liệu** (Cơ sở dữ liệu MySQL/SQLite và Hệ thống tệp tĩnh).
5.  Tầng Dịch vụ đóng gói phản hồi dạng định dạng JSON chuẩn hóa để trả về cho Client hiển thị trực quan lên màn hình.

## 3.5.2. Chi tiết thiết kế các Tầng Kiến trúc

### A. Tầng Trình diễn (Presentation Layer)
Lớp trình diễn đảm nhiệm vai trò giao diện tương tác người dùng (UI) và trải nghiệm người dùng (UX). Hệ thống hỗ trợ đa nền tảng nhằm đáp ứng tối đa nhu cầu vận hành thực tế tại bệnh viện:

1.  **Giao diện Ứng dụng Web (Web Client):**
    *   **Công nghệ chính:** HTML5, CSS3 (Vanilla CSS), Bootstrap 5, công nghệ nạp động dữ liệu Javascript (Fetch API) kết hợp với công cụ tạo khuôn mẫu Jinja2 Templates được phục vụ trực tiếp từ máy chủ FastAPI.
    *   **Dashboard phụ trợ:** Sử dụng Streamlit (`app.py`) làm công cụ trực quan hóa nhanh phục vụ công tác nghiên cứu phát triển (R&D) và kiểm thử thực địa mô hình AI, hỗ trợ kéo trượt điều chỉnh ngưỡng xác suất lâm sàng tức thì.
2.  **Ứng dụng Di động (Mobile Client):**
    *   **Công nghệ chính:** Flutter SDK (Dart).
    *   **Kiến trúc mã:** Thiết kế theo mô hình Clean Architecture kết hợp State Management (Provider/BLoC) giúp tối ưu hóa hiệu năng render, quản lý vòng đời ứng dụng mượt mà, hỗ trợ tương tác sâu với phần cứng thiết bị (Camera để chụp phim trực tiếp và Gallery để chọn tệp tin).

---

### B. Tầng Dịch vụ Ứng dụng (Application Service Layer)
Tầng dịch vụ là trái tim điều phối toàn bộ luồng nghiệp vụ của hệ thống, được thiết kế trên nền tảng **FastAPI** (Python) hiện đại với cơ chế bất đồng bộ (Asynchronous ASGI).

1.  **Thiết kế Các API Endpoints:**
    *   `POST /predict`: Endpoint nhận ảnh X-Quang ngực từ Mobile App, chạy suy luận AI, lưu trữ tệp tin và lưu trữ kết quả chẩn đoán vào database.
    *   `POST /api_predict`: Endpoint phục vụ Web App, tiếp nhận ảnh chụp kèm theo thông tin bệnh nhân (`patient_name`) và ghi chú lâm sàng của bác sĩ (`notes`).
    *   `GET /history`: Trả về danh sách lịch sử chẩn đoán dưới định dạng JSON cho ứng dụng di động.
    *   `GET /web-history`: Trả về giao diện bảng lịch sử phân trang phục vụ Web Client.
    *   `GET /api_stats`: Tính toán và trả về các chỉ số thống kê tổng quan (Tổng ca bình thường, tổng ca viêm phổi, độ tin cậy trung bình) phục vụ hiển thị Dashboard.
    *   `DELETE /history/{record_id}` & `GET /delete/{record_id}`: Xử lý yêu cầu xóa bản ghi lịch sử chẩn đoán khỏi DB và giải phóng tài nguyên ảnh tĩnh tương ứng trên đĩa cứng vật lý.

2.  **Cơ chế Tự động Chuyển đổi Dự phòng (Database Failover & Migration):**
    *   Máy chủ tích hợp công cụ kiểm tra kết nối CSDL khi khởi động. Nếu kết nối đến hệ quản trị MySQL chính gặp lỗi (ngắt kết nối mạng, quá tải), hệ thống sẽ tự động hạ cấp xuống CSDL SQLite nhúng cục bộ (`pneumonia.db`) để ứng dụng tiếp tục hoạt động không bị gián đoạn.
    *   Tích hợp sẵn module tự động di trú cấu trúc bảng (`run_migrations`) giúp tự động kiểm tra và thêm các cột dữ liệu còn thiếu (`patient_name`, `notes`, `heatmap_url`) vào cấu trúc DB cũ.

---

### C. Tầng Suy luận AI (AI Inference Layer)
Tầng này đảm nhận việc tính toán nặng nhất hệ thống, chạy trên nền tảng PyTorch dưới dạng luồng xử lý độc lập để đảm bảo không chặn (non-blocking) luồng API chính.

1.  **Kiến trúc Mô hình Học sâu HybridViT:**
    Mô hình áp dụng kỹ thuật lai ghép giữa mạng tích chập CNN truyền thống (đại diện cho khả năng trích xuất đặc trưng cục bộ xuất sắc) và mạng Transformer (đại diện cho khả năng học mối quan hệ không gian toàn cục mạnh mẽ):
    *   **CNN Backbone (DenseNet121):** Ảnh đầu vào kích thước `224x224x3` được đưa qua DenseNet121 được đóng băng các lớp đầu để giữ lại các đặc trưng cạnh/góc cơ bản của ảnh y tế. Dữ liệu đi qua đến lớp `denseblock3` trích xuất ra tensor đặc trưng có chiều sâu lớn (`1024 channels`).
    *   **Patch Embedding (Conv2d 1x1 + Rearrange):** Sử dụng tích chập 1x1 để giảm số lượng kênh từ 1024 xuống chiều ẩn `embed_dim=512`, sau đó sắp xếp lại không gian phẳng hóa thành chuỗi `(14 * 14) = 196` tokens.
    *   **Vision Transformer (ViT):** Bổ sung Class Token (`cls_token`) học đặc trưng đại diện phân loại chung và Position Embedding (`pos_embed`) để giữ thông tin vị trí các vùng phổi trong ảnh. Chuỗi token đi qua **6 lớp Transformer Block** liên tiếp (Mỗi block gồm Multi-Head Attention, MLP và Layer Normalization).
    *   **Classification Head:** Class Token đầu ra được đưa qua lớp chuẩn hóa LayerNorm và lớp tuyến tính (Linear layer) để phân loại thành 2 lớp: **BÌNH THƯỜNG (NORMAL)** hoặc **VIÊM PHỔI (PNEUMONIA)**.

2.  **Module Trực quan hóa Giải thích AI (GradCAM Module):**
    Để phá vỡ rào cản "hộp đen" của AI trong y tế, module GradCAM được thiết kế để trực quan hóa vùng mô hình tập trung đưa ra quyết định:
    *   Đăng ký **Forward Hook** tại lớp đích `model.backbone.denseblock3` để trích xuất bản đồ kích hoạt đặc trưng không gian $A$.
    *   Đăng ký **Backward Hook** để lấy các gradients đạo hàm riêng $Q$ của điểm số lớp dự đoán $y^c$ đối với các bản đồ kích hoạt: $\frac{\partial y^c}{\partial A}$.
    *   Tính toán trọng số kênh $\alpha_k^c$ bằng cách lấy trung bình toàn cục không gian (Global Average Pooling) của gradients:
        $$\alpha_k^c = \frac{1}{H \times W} \sum_{i=1}^{H} \sum_{j=1}^{W} \frac{\partial y^c}{\partial A_{i,j}^K}$$
    *   Tích hợp tuyến tính bản đồ kích hoạt kết hợp với hàm chỉnh lưu ReLU để chỉ giữ lại các đặc trưng có tác động tích cực đến lớp chẩn đoán lựa chọn:
        $$L_{GradCAM}^c = ReLU\left(\sum_{k} \alpha_k^c A^k\right)$$
    *   Bản đồ nhiệt được nội suy bilinear về kích thước `224x224`, làm mịn bằng Gaussian Blur và lồng ghép (Overlay) trực tiếp lên ảnh gốc chụp phổi với hệ số pha trộn $\alpha = 0.55$.

### D. Tầng Dữ liệu và Lưu trữ (Data Layer)
Tầng dữ liệu đảm bảo tính nhất quán, lưu trữ lâu dài thông tin lịch sử khám bệnh và các tệp tin hình ảnh tĩnh liên quan.

1.  **Thiết kế Thực thể Dữ liệu (ORM Table Schema):**
    Bảng dữ liệu `diagnosis_history` được ánh xạ thông qua SQLAlchemy ORM với cấu trúc chi tiết như sau:

| Tên Trường (Field) | Kiểu Dữ Liệu | Ràng Buộc | Mô Tả |
| :--- | :--- | :--- | :--- |
| `id` | `Integer` | Khóa chính, Tự tăng | Mã định danh duy nhất của ca khám bệnh. |
| `patient_name` | `String(100)` | Cho phép NULL | Họ và tên của bệnh nhân chẩn đoán. |
| `patient_age` | `Integer` | Cho phép NULL | Tuổi của bệnh nhân chẩn đoán. |
| `image_url` | `String(255)` | NOT NULL | Đường dẫn URL tương đối tới tệp ảnh X-Quang gốc. |
| `heatmap_url` | `String(255)` | Cho phép NULL | Đường dẫn URL tương đối tới tệp ảnh bản đồ nhiệt. |
| `gradcam_url` | `String(255)` | Cho phép NULL | Đường dẫn URL tương đối tới ảnh lồng ghép GradCAM. |
| `label` | `String(50)` | NOT NULL | Nhãn chẩn đoán của mô hình AI (`NORMAL` / `PNEUMONIA`). |
| `confidence` | `Float` | NOT NULL | Độ tin cậy dự đoán (khoảng $[0, 1]$). |
| `normal_prob` | `Float` | NOT NULL | Xác suất phổi bình thường. |
| `pneumonia_prob`| `Float` | NOT NULL | Xác suất viêm phổi. |
| `timestamp` | `DateTime` | Mặc định: `UTC Now`| Ngày giờ thực hiện phân tích lâm sàng. |
| `notes` | `Text` | Cho phép NULL | Nhận xét/ghi chú lâm sàng của bác sĩ điều trị. |
| `severity_json` | `Text` | Cho phép NULL | Dữ liệu cấu trúc mở rộng (đánh giá mức độ nghiêm trọng). |

2.  **Hệ thống Lưu trữ Tệp (Static File Storage):**
    Tất cả các tệp hình ảnh được quản lý khoa học trên máy chủ tại thư mục tĩnh phục vụ nhanh:
    *   Ảnh gốc lưu trữ tại: `webapp/static/uploads/{UUID}.png` để tránh trùng lặp tên file.
    *   Ảnh bản đồ nhiệt lưu trữ tại: `webapp/static/gradcam/heatmap_{UUID}.png`
    *   Ảnh lồng ghép (Overlay) lưu trữ tại: `webapp/static/gradcam/gradcam_{UUID}.png`

```
      │                          │                          │                          ││ Phân loại   │           │
```

Sự phân tách kiến trúc rõ ràng giữa 4 tầng này giúp đảm bảo hệ thống chẩn đoán **PneumoScan AI** vận hành với độ trễ cực thấp (dưới 0.5 giây đối với toàn bộ luồng xử lý), có tính bảo mật cao nhờ ẩn giấu trực tiếp cấu trúc AI đằng sau cổng dịch vụ API và sẵn sàng cho việc tích hợp vào hệ thống lưu trữ và truyền thông hình ảnh y tế PACS/DICOM của các bệnh viện lớn trong tương lai.
